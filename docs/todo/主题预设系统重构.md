# 主题预设系统重构

## 背景

当前多语言/翻译系统存在三个问题：
1. UI 翻译走 Localization 系统（`.bin` 文件，从 SD 卡加载），设计合理
2. BGM 翻译硬编码在 `BgmTranslations.h`（155 条），用户新增 BGM 无法翻译
3. 主题翻译硬编码在 `ThemeAdapter.h`（14 条），用户新增主题无法翻译

在讨论翻译方案时发现更深层的问题：当前的"主题"只是换皮肤（背景图），BGM 要单独选，颜色跟 Material 走——这些本应是一个完整的"主题预设"概念。

## 设计思路

参考 Windows 主题系统：
- **主题 = 预设方案**，把皮肤 + BGM + 配色 + 深色模式打包在一起，一键切换
- 但各个组成部分也可以**单独调整、自由混搭**
- 混搭满意后可以**保存为新预设**

## 架构方案

### 独立资源（用户可单独选择混搭）

```
/_pico/
├── skins/                    ← 外观皮肤（原来的 themes/）
│   ├── Minecraft v0.1/
│   │   └── skin.cfg          ← 皮肤元数据（显示名等）
│   ├── Rainbow/
│   └── ...
├── bgm/                      ← 背景音乐（保持现有结构）
│   ├── 3DS/
│   │   ├── names.cfg         ← 该平台文件夹的 BGM 显示名
│   │   └── *.bcstm
│   ├── DSi/
│   └── ...
└── settings.json             ← 当前选择
```

### 预设主题（一键组合）

```
/_pico/presets/
├── 经典怀旧.cfg
├── 赛博朋克.cfg
└── 用户自定义.cfg
```

### 预设文件格式

```ini
skin=Minecraft v0.1
bgm=Nintendo_Wii_Music__Menu
dark_mode=off
color=auto
```

### 翻译方案

| 内容 | 翻译位置 | 说明 |
|------|----------|------|
| UI 文字 | `/_pico/extras/translations/Chinese.bin` | 保持现有机制 |
| BGM 显示名 | 每个平台文件夹的 `names.cfg` | 跟着资源走，不冲突 |
| 皮肤显示名 | 每个皮肤文件夹的 `skin.cfg` | 跟着资源走，不冲突 |
| 预设显示名 | 预设文件名本身就是显示名 | 无需额外翻译 |

### 用户体验

1. 设置菜单展示：预设主题 / 皮肤 / BGM / 配色 / 深色模式（分开的选项）
2. 选"预设主题" → 一键切换整套方案
3. 也可以单独进各子项自由混搭
4. 混搭满意 → 保存为新预设

### 整合包兼容性

整合包解压后各资源归各自目录，互不覆盖：
```
整合包.zip/
├── _pico/skins/新皮肤/       ← 自带 skin.cfg
├── _pico/bgm/新平台/         ← 自带 names.cfg
├── _pico/presets/新预设.cfg  ← 可选
└── _pico/covers/nds/         ← 封面直接覆盖不冲突
```

## 涉及改动

- [ ] `themes/` 重命名为 `skins/`，ThemeAdapter 适配
- [ ] 新增 `presets/` 目录和预设加载逻辑
- [ ] 设置菜单 UI 重构（拆分为预设/皮肤/BGM/配色/深色模式）
- [ ] 新增 `NameConfig` 类：读取 `names.cfg` / `skin.cfg`
- [ ] 删除 `BgmTranslations.h` 硬编码翻译表
- [ ] 删除 `ThemeAdapter.h` 硬编码翻译表
- [ ] 写工具脚本：从现有硬编码表导出 `names.cfg` / `skin.cfg`
- [ ] 写工具脚本：批量为现有 BGM/皮肤生成元数据文件
- [ ] settings.json 格式扩展（增加 preset 字段）
- [ ] 预设保存功能（用户混搭后保存为新预设）

## 优先级

这是一个较大的重构。建议分阶段：

1. **阶段一**：先解决翻译问题（names.cfg / skin.cfg），删除硬编码
2. **阶段二**：实现预设系统（presets/），一键切换
3. **阶段三**：设置菜单 UI 重构，支持混搭 + 保存预设
